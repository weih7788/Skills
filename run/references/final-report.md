# Final Report

## 默认汇报格式

最终回复应短而清楚，优先说明用户关心的结果。

```markdown
已按方案完成实现，核心变化是……

验证：已运行 `command`，结果通过。

注意：还有一个未覆盖风险……（如果没有就省略）
```

## 较复杂任务格式

当改动跨多个模块或验证较多时，使用下面结构：

```markdown
## 完成内容

- 实现了……
- 调整了……

## 验证

- 已运行 `command-a`，通过。
- 已运行 `command-b`，通过。

## 偏差与风险

- 原方案计划……，实现时发现……，因此改为……。
- 未运行……，原因是……。
```

## 汇报要求

- 不重复粘贴大段代码。
- 不把文件清单写成流水账，除非用户需要 review 指引。
- 测试没跑就明确说没跑，不写成“应该没问题”。
- 有偏差就写偏差，没有偏差可以省略该段。
- 如果还有用户需要手动确认的事项，放在最后并保持简短。
