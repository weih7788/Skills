## 企业微信表格的可复制粘贴交付（唯一方式）

用户已确认企业微信在线表格只采用人工复制粘贴方式。选择企业微信表格为目标时，完成只读核对和本技能要求的预修改清单后，交付**可直接复制到目标工作表的制表符分隔文本（TSV）**，由用户自行粘贴；交付文本不等于在线更新，不声称已写入或回读。不要尝试本 Agent 在线编辑、自动化写入或生成交给企业微信内置 AI 的编辑提示词；这些方案已确认走不通。网站 API 文档仍按原有自动化流程保存草稿并回读，已确认的创建订舱请求参数变更必须同步离线工作簿。

- 先核实目标页签、表头及字段层级。创建订舱任务请求参数页的新增行按同一父级下连续插入的位置分组；每组写明**准确前后锚点和需插入的空行数**，随后给出单独的 `tsv` 代码块。代码块内只放数据行，不放表头、行号或说明；每行对应 A:G 的一级报文、二级报文、三级报文、壹沓标准字段、参数类型、报文说明、通用取值说明。用真实 Tab 分隔，保留 A-C 的空单元格与正确层级；没有可靠值的单元格留空，不写占位提示。若 G 列全空，可交付 A:F 六列，并明确 G 及船司列保持空白。
- 同一父级有多处不连续插入位置时分别给代码块；不能把全部新增字段拼成一个连续块，导致父子层级或相邻字段错位。粘贴前需插入空行，不能覆盖现有行；保留原工作表其他船司列及原有格式。拟更新现有行时，按完整路径标出原单元格和目标列，给出可单独粘贴的值；只有相邻单元格都已核实且均需修改时才提供多列 TSV。字段改名、删除、移动和完整 JSON 示例单独列明，不混入新增行 TSV。

## 示例值与脱敏规则

- 参数表只写有依据、适用于该字段路径和业务场景的示例值。找不到可靠示例时，在线文档的“示例值”单元格直接留空；不得写 `⚠️`、`待提供`、`[示意]` 等提示或凭空编造业务枚举。**仅对因脱敏而不能展示原值、且已确认字段格式的示例，可写明显虚构的同类型值**，例如测试账号或 `example.com` 邮箱；在审核清单注明是虚构示例，不把提示写入目标单元格。字段描述仍按代码证据处理；缺少可核实业务说明时，在线文档的“描述”单元格直接留空，不写 `⚠️【待提供业务说明】` 等占位文本。审核清单在字段无代码注释时于字段名前标 `⚠️ 无代码注释`，并在处理说明注明“描述留空／缺少依据”；提醒不得写入拟写描述单元格，也不得编造定义。
- 请求／响应 JSON 中必须脱敏的字段，及原来用“订舱账号用户名”“收货地代码”“船名”等业务含义文字占位的字段，改用**明显虚构、格式和 JSON 类型相符的具体值**。例如 `userName` 可写 `"demo_booking_001"`，`bkgMail` 可写 `"booking@example.com"`，日期写 `yyyy-mm-dd` 形式，五字码取有依据的标准代码，重量保持原字段的字符串或数值类型。密码只能放虚构密文形态，不能放真实凭证或会被误认为可复用的明文密码；没有密钥时不得宣称示例密文可实际解密。枚举值要用已核实的合法值，无法确认时不编造或在完整 JSON 中省略该字段并在审核清单说明。对外文档的标题和说明不写“脱敏”“非可直接提交”等处理提示；这类说明只放在审核清单或对话中。不得保留真实凭证、联系方式或客户数据，也不得混用不同订单的真实取值。相关方企业名称、地址只能采用明显虚构的示例主体，不能写真实客户名称。

- 创建订舱任务的请求示例以船司代码标识；官网渠道标题只写船司代码，非官网渠道在船司代码后标明渠道，WHL 在标题中标明网点。同一船司如有不同渠道或 WHL 不同网点，按场景分别保留完整 JSON 示例，不混用。渠道名称以当前代码枚举及报文中的 `bookingChannel` 核对，网点以报文中的网点字段和业务映射核对；无法核实则不猜测。标题不附加“生产请求结构参考”“脱敏”“非可直接提交”等面向内部审核的提示。保留各示例的字段结构与 JSON 类型，把业务含义占位词改成虚构具体值，并检查每段 JSON 可解析及同一示例内港口、日期、船名航次和相关方相互一致。

## 每次执行
