# 将后端实现方案补充到现有需求文档

## 目标与边界

输入需求 ID，从工作区已有的需求文件中找到该 ID 对应的需求，从当前后端代码还原实际实现，只新增或更新需求中的 `实现方案 → 后端`。这是已实现代码的追溯记录，不是重新设计方案。原需求的背景、描述、范围、状态、其他端的方案、评论和附件保持原样。

**仅使用工作区内已有的需求文件和证据，不访问云效或其他在线工作项，也不为核对需求重新拉取外部数据。**优先使用用户指定的需求文件；未指定时，按项目现有配置定位该 ID 的本地需求文档。导出的 JSON、评论和附件等本地材料用于核对，不代替目标需求文档。不得把更新本地文件表述成已更新在线工作项。

## 工作流程

1. **定位需求与目标**：从当前项目最近的配置或用户给定路径定位本地需求文件。按完整 ID 核对标题、项目和正文；只读取工作区内已有、且直接影响需求范围的评论、变更及附件材料。若只找到 ID 而没有正文，停止补写并说明缺口，不凭编号编造需求，也不访问云效补取。若有多个同名副本，先判定目标文件与核对材料。
2. **核对后端实现**：从当前代码分支、相关提交和实际调用链读取回执／请求模型、业务处理、持久化、对外响应或推送，以及相关测试。记录准确的类、方法、字段、接口名和提交。区分“代码已实现”“测试已验证”“环境已部署”；上游服务或客户系统不在可读范围时，不把整条链路写成已核实。
3. **形成追加内容**：用需求文档现有语言写 `## 实现方案` 下的 `### 后端`，按数据进入、处理／存储、对外输出的顺序说明做法和关键字段。只写能由代码证明且与该需求直接相关的行为。其他端的实现需要记录时，必须有相应证据和用户要求；本技能默认只写后端。
4. **最小编辑**：原文没有 `实现方案` 时，在末尾追加该模块；已有模块但没有 `后端` 时，只插入 `### 后端`；已有后端小节时，仅更新该小节。对 Markdown 使用局部补丁。不要顺手改标题、日期、旧核验结论、链接或其他章节。不能原位编辑时，给出可粘贴的后端模块并说明未写入。
5. **核验写入**：写前保存原文，写后重新读取。比较差异，确认变化仅限新增／更新的后端实现小节，且原有正文与附件仍在。报告实际更新的本地需求文件、代码依据、未核实的边界，并明确在线工作项未更新。

## 内容模板

```markdown
## 实现方案

### 后端

1. **接收／入口**：实际接口、入参和字段映射。
2. **处理与保存**：实际业务规则、关键方法和存储位置。
3. **对外输出**：响应或推送字段、取值口径及兼容行为。

代码依据：相关文件与提交。未核实的外部链路：仅在确有缺口时说明。
```

模板是内容骨架，不要求为没有对应行为的需求凑齐三项。实现口径与原需求冲突时，在后端小节明确指出差异，不改写原需求来掩盖冲突。
