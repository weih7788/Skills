# UI Generate

## Role

这是 UI 交互图生成入口 skill。它用于把需求或项目上下文中的页面交互，整理成可确认的连续操作图组，并生成截图风格或产品原型风格的位图图片。

它只负责四件事：

1. 从上下文抽取 UI 交互需求、用户路径、页面状态和待确认点
2. 先整理交互流程或 UI 描述，并提供给用户确认；根据用户反馈迭代到明确可出图
3. 将确认后的交互拆成一组或多组连贯操作，每组图体现同一用户完成一个完整任务
4. 基于项目视觉上下文生成位图交互图，或输出可复制到其他图片模型的提示词，并说明每组图对应的交互意图

## Bottom Rules

1. **先梳理交互再确认**。生成图片前，必须先明确用户角色、入口、目标、操作步骤、页面状态和反馈结果，并把交互流程或 UI 描述提供给用户确认。
2. **必须等待明确确认后再出图**。用户尚未确认交互流程或 UI 描述时，不生成图片；用户提出调整时，先更新交互说明并再次确认，可经历多轮确认。
3. **一组图必须连贯**。每组交互图要体现用户的一组连续操作，例如“进入列表 -> 打开筛选 -> 查看结果 -> 进入详情”，不能把互不相关的页面拼成一组。
4. **可以生成多组图片**。当需求包含多个任务、角色或关键分支时，拆成多组图；每组只承载一个清晰操作目标。
5. **主题色优先来自项目上下文**。先从截图、设计稿、CSS 变量、主题配置、组件库 token、Tailwind 配置、Less/Sass 变量、Figma/文档说明或现有页面中提取主色、辅助色、背景色和状态色。
6. **同项目主题必须一致**。同一个项目内的所有图组必须使用同一套主色、辅助色、背景色、状态色、组件圆角、阴影、字号层级和信息密度；不能因为图组不同而切换色调或设计风格。
7. **没有主题上下文时保持克制**。无法确认项目主题色时，使用简约、低饱和度配色；避免高饱和渐变、大面积紫蓝渐变、装饰性光斑和营销化视觉。
8. **生成真实可评审的位图**。需要使用图片生成能力产出截图风格或产品原型风格图片；不能用 Mermaid、ASCII、文字流程或抽象线框替代用户要求的交互图。
9. **支持交付可复制提示词**。当用户要求在其他模型生成图片，或当前环境不适合直接出图时，输出完整图片生成提示词；提示词必须能独立表达交互、布局、主题、尺寸、组图拼接和质量约束。
10. **提示词只能输出一段**。即使存在图组 A、图组 B、图组 C，也必须输出一个完整提示词块；在同一段提示词里分段描述各图组，不为每个图组分别输出独立 prompt。
11. **App 图使用 iPhone 15 比例**。如果 UI 图是 App 或移动端应用，单屏图片按 iPhone 15 竖屏比例生成，优先使用 `1179x2556` 或等比例尺寸；不要混用宽高比。
12. **连续动作组图必须完整拼接**。如果多张图片属于同一组连续动作，最终应拼成一张组图，按步骤顺序横向或纵向排列；每个屏幕必须完整显示，不得裁切、遮挡、缺页、缺内容或压缩到不可读。
13. **不要提前实现代码**。除非用户明确要求落地前端代码，本 skill 只生成交互说明、图片或提示词，不修改项目代码。
14. **不把假设写成事实**。项目主题色、组件规范、权限和页面行为无法确认时，必须标为假设或待确认。

## Context Collection

按需读取最小充分上下文：

- 用户提供的 PRD、需求文档、会议纪要、截图、草图、页面链接或设计说明
- 当前项目中的路由、页面组件、菜单配置、表单、列表、详情、弹窗和状态组件
- 主题相关文件：`theme`、`tokens`、`variables`、`tailwind.config`、`vite.config`、`styles`、`scss`、`less`、`css`、`ant-design`、`element-plus`、`material` 等
- 现有页面中的信息密度、组件圆角、字号层级、按钮样式、表格/卡片/表单布局、空态/加载态/错误态

如果用户没有给出项目文件或截图，基于需求文本生成低保真但清晰的产品原型风格图片，并说明视觉假设。

## Workflow

### 1. Extract Interaction Requirements

先输出或内部整理以下内容：

- 目标用户和使用场景
- 页面入口和前置条件
- 用户要完成的任务
- 连续操作步骤
- 每步对应的界面状态、用户输入、系统反馈
- 成功态、失败态、空态、加载态、权限不足或数据冲突等关键分支
- 用户最需要确认的布局、字段、按钮、提示文案和状态变化

### 2. Confirm Interaction Description

在生成任何图片前，先把交互流程或 UI 描述发给用户确认。内容应包括：

- 本次准备生成的图组范围
- 每组图覆盖的用户目标和连续操作
- 每张图的页面、步骤、关键组件、主要状态和反馈
- 已采用的主题依据或默认视觉假设
- 需要用户确认的少量关键问题

如果用户提出修改，先更新交互流程或 UI 描述，再次请求确认。只有当用户明确表示确认、可以生成、按这个出图、没问题或同等意思后，才进入图片生成。

### 3. Group Storyboards

将交互拆为图组。每组建议 2-5 张图，复杂任务可增加，但要保持同一目标：

- `图组 A：主流程`，例如“创建活动：入口 -> 填写表单 -> 预览确认 -> 创建成功”
- `图组 B：异常分支`，例如“库存不足：选择商品 -> 提交 -> 错误提示 -> 修改后成功”
- `图组 C：管理操作`，例如“审批订单：列表筛选 -> 打开详情 -> 审批弹窗 -> 状态更新”

每张图必须标明：

- 所属图组和步骤编号
- 页面或组件名称
- 当前用户动作
- 需要展示的关键 UI 状态

### 4. Resolve Visual Theme

优先从项目上下文提取主题：

- 主色：品牌按钮、链接、选中态、导航高亮
- 辅助色：标签、图标、弱强调区域
- 背景色：页面背景、面板背景、边框
- 状态色：成功、警告、错误、禁用、进行中
- 组件风格：圆角、阴影、边框密度、字号层级、表格/卡片/表单偏好

为同一个项目建立一份统一的视觉基线，并在所有图组中复用。后续图组只能因状态含义切换状态色，例如成功、警告、错误，不能改变整体主题色调、组件风格、插画风格、背景氛围或信息密度。

若未找到主题，使用默认视觉假设：

- 低饱和蓝灰为主色，搭配柔和青绿或琥珀作状态强调
- 白色或浅灰页面背景，深灰正文，细边框，少阴影
- 面向后台系统时优先表格、表单、筛选栏和紧凑信息层级
- 面向移动端时优先底部导航、列表、详情页和清晰触控目标

### 5. Generate Images Or Prompts

仅在用户已经确认交互流程或 UI 描述后执行本步骤。

使用可用的图片生成能力生成位图。若当前环境提供 `imagegen` skill 或图片生成工具，优先使用它。若用户要求“输出提示词”“给我 prompt”“我拿去别的模型生成”，则不要只描述图片，应输出可直接复制的完整提示词。

图片提示词必须包含：

- 输出风格：截图风格或产品原型风格，清晰、可评审、非营销海报
- 设备和尺寸：桌面 Web、移动端、平板或响应式视口；App 或移动端应用必须指定 iPhone 15 竖屏比例，优先 `1179x2556` 或等比例
- 图组和步骤：明确这是连续操作中的第几步
- 页面结构：导航、标题区、筛选栏、表格、表单、详情、弹窗、Toast、空态等
- 用户动作和系统反馈：点击、输入、选择、提交、校验、成功、失败
- 主题来源：项目已有主题色，或“简约低饱和主题”
- 项目一致性：同一项目所有图组使用同一套主题色、组件风格、字体层级、圆角、阴影和信息密度
- 约束：文字不重叠，按钮/表单/表格可读，状态变化明显，不使用纯装饰背景
- 组图要求：同一组连续动作需要合成为一张完整组图，所有步骤屏幕按顺序排列，屏幕边界清楚，不裁切、不缺内容、不遮挡

当一次需要多张图时，保持同一图组内的布局、色彩、字号、组件风格和数据对象一致，只改变操作状态。同组连续动作最终交付为一张组图。如果模型能力限制无法一次生成组图，也仍然只输出一个整体提示词；在这一个提示词中同时描述每个单屏和组图拼接要求，不能拆成多个独立提示词。

### Prompt Output Format

当输出可复制提示词时，整个项目只提供一个 fenced code block。即使包含图组 A、图组 B 或更多图组，也必须把所有图组写进同一个完整 prompt 中，不能为每个图组分别输出一个 code block 或一段独立提示词。

这个唯一提示词应包含：

- `整体用途`：本项目要生成哪些图组，以及每组图要表达的连续操作
- `统一尺寸`：Web、移动端或 iPhone 15 比例；若各图组设备不同，也在同一 prompt 中说明
- `统一主题`：同一项目共用的主题色、组件风格、字体层级、圆角、阴影和信息密度
- `图组说明`：在同一 prompt 内描述图组 A、图组 B、图组 C 的步骤、页面和状态
- `组图拼接`：每个图组分别拼成一张完整组图，所有屏幕完整可见
- `负向约束`：不得裁切、不得缺屏、不得文字重叠、不得装饰喧宾夺主等

示例结构：

```text
整体用途：为同一个项目生成两张连续操作组图：图组 A 展示用户完成创建活动的主流程，图组 B 展示提交失败后的修改重试流程。
统一尺寸：iPhone 15 portrait, 1179x2556 per screen; each group combines its screens into one complete storyboard image.
统一主题：...
图组 A：...
图组 B：...
组图拼接：图组 A 输出为一张完整组图，图组 B 输出为一张完整组图；所有屏幕按步骤顺序排列，边界清楚，完整可见。
负向约束：no cropping, no missing screens, no overlapping text, no unreadable UI, no decorative poster style
```

### 6. Deliver Result

交付时包含：

- **交互需求摘要**：角色、目标、入口和关键流程
- **主题依据**：列出已提取的主题色/组件风格；没有上下文时说明默认视觉假设
- **图组清单**：每组图片覆盖的连续操作和每张图的步骤说明
- **生成图片或提示词**：按图组顺序展示图片，或提供可复制到其他模型的提示词
- **待确认点**：字段、流程、状态、权限或视觉假设中最需要用户确认的少量问题

## Final Check

输出前确认：

- 已从上下文梳理 UI 交互需求，而不是直接跳到画图
- 已将交互流程或 UI 描述提供给用户确认，并在用户明确确认后才生成图片
- 如果用户多轮调整，已先更新说明并重新确认
- 每组图体现了一组连贯操作，且组间边界清晰
- 图片主题优先复用项目已有主题色；无法确认时已使用简约低饱和主题并说明假设
- 同一项目中的所有图组主题色调、组件风格和视觉密度保持一致
- 图片能展示关键页面、组件、操作和反馈状态
- 如果输出提示词，提示词可独立复制使用，并包含尺寸、主题、组图、步骤和负向约束
- 如果有多个图组，提示词仍然只有一个完整 prompt，而不是按图组拆成多段 prompt
- 如果是 App 图，已按 iPhone 15 竖屏比例描述或生成
- 如果多张图是一组连续动作，已要求拼成一张完整组图且不得裁切、缺屏或缺内容
- 同组图片视觉一致，文字清晰，没有重叠或明显错位
- 已说明每张图对应的操作步骤和待确认点
- 没有在用户未要求时代码实现或修改项目文件
